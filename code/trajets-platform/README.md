# Trajets — on the platform

Generated by simple-mda from a platform application: edit the model, not
these files. A single npm project on the published `@kogitec/*` packages:
the server of the platform serves the application and its interface.

## Run

1. Create a GitHub token with the `read:packages` scope: the `@kogitec/*`
   packages are published on GitHub Packages.
2. Put it in `NODE_AUTH_TOKEN`: `export NODE_AUTH_TOKEN=<the token>`.
3. Start MongoDB 7 as a replica set:

   ```bash
   docker run -d --name trajets-mongo -p 27017:27017 mongo:7 --replSet rs0
   docker exec trajets-mongo mongosh --quiet --eval 'rs.initiate({_id:"rs0",members:[{_id:0,host:"localhost:27017"}]})'
   ```

4. `npm install`.
5. `npm start` — builds the interface, then starts the server.
6. Open `http://localhost:8081`.

`MONGO_URL` names the database (by default `mongodb://localhost:27017/kogitec`),
`PORT` the port. Without MongoDB the server starts, says so once, and the
lists of the entities without a table stay empty. Under `npm start` the
sign-in is not required: without a sign-in provider (`OAUTH_*`) the
application opens as « Développeur local ». `npm run typecheck` checks the
types. « Configure the server » names every variable the server reads.

## An existing PostgreSQL base

These entities live in a table of an existing PostgreSQL base. The server
reads and writes their rows; it never creates, alters or drops a table or
a column.

- `Trajet`: the table `kitchen_trips`

Point the server at the base before `npm start`:

| Variable | What it says | Default |
| --- | --- | --- |
| `POSTGRES_URL` | The base: `postgres://user:password@localhost:5432/base` | none: each read of these entities is refused |
| `POSTGRES_PUBLICATION` | The publication the server follows | `platform` |

```bash
POSTGRES_URL=postgres://user:password@localhost:5432/base npm start
```

At start-up the server says once whether the base answers:

```text
[schema] PostgreSQL answers at postgres://user:***@localhost:5432/base: connected
```

The account of the base reads and writes these tables (`SELECT`, `INSERT`,
`UPDATE`, `DELETE`) and uses their sequences. The writes of the
application are always seen live; to see live what other applications
write, the base needs `wal_level = logical`, the account the `REPLICATION`
right, and a publication of these tables. « Set the base for live changes —
once » of the guide of the platform says how, once:
https://github.com/Kogitec/platform/blob/develop/docs/platform/schema/postgres.md.
Without them the server says so once and goes on.

MongoDB keeps only the entities without a table. Without it, the server
starts, says so once, and serves these tables all the same.

## Build the image

The `Dockerfile` builds the project into an image that builds its interface
and serves it from the start. The token is passed as a build secret, read by
the install only: no layer of the image keeps it. From this folder:

```bash
NODE_AUTH_TOKEN=<the token> docker build --secret id=node_auth_token,env=NODE_AUTH_TOKEN -t trajets .
```

The build needs BuildKit, the default of Docker since version 23. The
versions of the packages are those of `package-lock.json` when there is one,
else the latest the ranges of `package.json` allow.

The image requires the sign-in (`REQUIRE_AUTH=true`). Started without a
sign-in provider, it does not start, and its log names what is missing:

```text
server not started: REQUIRE_AUTH=true needs an identity provider: set OAUTH_ISSUER, OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET
```

To try it on a computer, `REQUIRE_AUTH=false` opens the session of
« Développeur local », and the MongoDB of « Run » is reached through the host:

```bash
docker run --rm -p 8081:8081 -e REQUIRE_AUTH=false \
  --add-host=host.docker.internal:host-gateway \
  -e 'MONGO_URL=mongodb://host.docker.internal:27017/kogitec?directConnection=true' \
  trajets
```

Then open `http://localhost:8081`. Keep `directConnection=true`: without it,
the driver follows the replica set to `localhost:27017`, which inside the
container is the container itself, and the lists stay empty.

## Configure the server

The server reads its settings from the environment only.

| Variable | What it says | Without it |
| --- | --- | --- |
| `PORT` | The port of the server | `8081` |
| `MONGO_URL` | The MongoDB base of the entities without a table | `mongodb://localhost:27017/kogitec`, which inside a container is the container itself: the server says once that MongoDB does not answer, the lists of these entities stay empty, and it connects by itself when MongoDB answers |
| `POSTGRES_URL` | The PostgreSQL base of the entities that name a table | Each read of such an entity is refused, and the log says so at each read: `[schema] Schema <Entity> refused: POSTGRES_URL is not set`. A project without such an entity does not need it |
| `POSTGRES_PUBLICATION` | The publication the server follows to see live what other applications write | `platform` |
| `REQUIRE_AUTH` | `true` requires a session for every page and every live exchange | `true` in the image. Under `npm start` the sign-in is not required: every visitor gets the session of « Développeur local », which reads and writes everything |
| `OAUTH_ISSUER`, `OAUTH_CLIENT_ID`, `OAUTH_CLIENT_SECRET` | The sign-in provider and the client registered with it | Under `REQUIRE_AUTH=true` the server does not start and names the missing ones: `server not started: REQUIRE_AUTH=true needs an identity provider: set OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET` |
| `ROOT_URL` | The public address of the server, where the sign-in comes back | The log says `REQUIRE_AUTH is set without ROOT_URL; socket.io connections are checked for a session only, not for the page that opens them.` The sign-in comes back to `http://localhost:<PORT>/auth/callback`, and the live exchanges are accepted from any page |
| `SESSION_SECRET` | The key of the session cookies | A key drawn at start-up, and the log says so at the first sign-in: `SESSION_SECRET is not set; generating an ephemeral key.` Every restart signs everybody out |
| `PLATFORM_ROLES` | The roles, in JSON, from each role to the email addresses or the client ids that hold it: `{"admin":["someone@example.com"]}` | Every person has the base role `user` only. A value that is not JSON stops the server: `server not started: PLATFORM_ROLES is not JSON: …` |
| `SCHEMA_ACCESS_DEFAULT` | `open` opens to everyone an entity that declares no right | Under `REQUIRE_AUTH=true` such an entity is refused to everyone, and the log names it at start-up: `[schema] no right declared, refused to every caller: <Entity>, …` |
| `MACHINE_CLIENT_IDS` | The machine clients, separated by commas, allowed in the live exchanges with a token | None: a live exchange that brings a token is refused without asking the sign-in provider |
| `TRUST_PROXY` | The proxies trusted in front of the server: `true`, `false`, a number of hops or a list of addresses | The nearest one (`1`): behind a proxy that says `X-Forwarded-Proto: https`, the cookies are `Secure` |
| `NODE_ENV` | `production` in the image: the server does not report the missing translation keys | Under `npm start` it reports them |

## `npm install` without a token

```
npm error code E401
npm error 401 Unauthorized - GET https://npm.pkg.github.com/@kogitec%2fcore - unauthenticated: User cannot be authenticated with the token provided.
```

`NODE_AUTH_TOKEN` is empty or has no `read:packages` scope: GitHub Packages
refuses to read the first `@kogitec/*` package. Steps 1 and 2 fix it. The
build of the image stops on the same `npm error code E401`; without any
token its second line ends with `authentication token not provided`.
